# bacnet-shifter — Threat assessment, 2026-10-29

A fresh assessment of the shifter as it is at `baa61ba`, after packages P1 to P5 of the [security plan](security-plan.md) were built and P6 cancelled. The [threat model](threat-model.md) of 2026-10-15 keeps the vocabulary (assets A1 to A7, zones, adversaries T1 to T6, threats S, T, R, I, D, E) and its §7 standings were updated as each package landed; this document does not repeat them. It asks three questions of the code as it stands: do the ten claims of threat model §8 hold when read against the code rather than the plan; what did the packages leave open or open anew; and what is the next thing to close. Every finding below was checked in the code at the lines cited, in this repository or in the `bacnet` library at v0.6.0 (`92cb28c`, two commits past the tag). Nothing was changed.

The one-sentence summary: **the disclosure control, the write guard, the consumer identity and the audit record hold as claimed; the bounds of P1 do not hold against a deliberate sender, because every per-source bound keys on something the sender chooses; and the site side trusts the library's address learning, which any site host can steer.** The shifter is a boundary toward an admitted consumer that behaves; it is not yet one toward a consumer that does not, and it is not one toward a rogue site device.

## 2. Findings

Severity is the harm to the assets of threat model §3 for the adversary who can reach the finding, given the setup the README requires (a tunnel on the consumer side, the host checklist). **High** means an admitted consumer or a site host can take an asset without any other weakness; **medium** means it takes a second condition, or the asset is availability of the shifter alone; **low** means a hardening gap with no clear path to an asset. Standing uses the threat model's words.

### 2.1 High

**F1. A Forwarded-NPDU's origin is believed from any sender.** Library. Threats S3, S2, E4, D2. `client/client.go:676-688`: when a datagram is a BVLC Forwarded-NPDU, the originating address in its header replaces the UDP source, for any carrier, whether or not a BBMD is configured, and after the `Exclude` and own-address checks ran on the carrier. The origin is then what the library and the shifter identify the sender by: reply matching by source and invoke ID (`client.go:776-782`), route learning (F2), the I-Am's address (`client.go:716-730`), the COV subscription key, and the shifter's move and duplicate tests (`shifter.go:485`).
Scenario: any host on the site network wraps an I-Am, a reply or a notification in a Forwarded-NPDU with the origin it chooses. With the origin of another site device it answers a pending request meant for that device, so a consumer's read returns the rogue's values and a write's acknowledgement is the rogue's; this is S3, which the model accepted on the ground that it needed IP-layer spoofing, and it needs none. With the origin of a consumer-side address it makes the shifter send the device's name read, probes and consumer-driven reads to that address from the site socket; on Linux and macOS the site socket is bound to every address, so the datagram leaves on the consumer adapter.
Standing: **gap**, and S3 moves from accepted to gap. The library's `forwarded_test.go:19` asserts the present behaviour. Closes with: believe a Forwarded-NPDU only from the configured BBMD, and never when none is configured; this is a library change, and the one the library's own scope allows, since it is the client's parsing.

**F2. Any datagram with a source network re-points that network's router.** Library. Threats S2, S3, D7. `client/client.go:770-774` and `routing.go:46-54`: every I-Am, reply and notification whose NPDU carries a source network makes its UDP sender the router for that network, overwriting whatever was learned, and so does any I-Am-Router-To-Network from any sender (`routing.go:73-79`). Every later request for the network goes to the last writer (`resolve`).
Scenario: a rogue site host sends one I-Am with SNET set to the number of a real routed network. From then on every read, subscription and write for every device on that network goes to the rogue, which answers as it likes; the real router hears nothing. A Reject-Message-To-Network from any sender fails every in-flight request to the network it names (`routing.go:90-98`), which is the lever for F8.
Standing: **gap.** No test covers a second announcer. Closes with: learn a route from I-Am-Router-To-Network only, keep the first router until it is silent or rejects, and log a conflicting claim; a library change.

**F3. A site reply grows the table by one record per device identifier it contains, with no admission check.** Shifter. Threats D5, D8, E4. `table.Reference` (`table.go:417-425`) makes a record for any instance that is not in the table; the translation rules call it for every application-tagged device identifier in any value of any reply or notification (`shifter.go:297-310`, `translate.go:263-268`), and for every device-address-binding entry. The admission bucket of P1 (`shifter.admit`, `shifter.go:472-482`) guards I-Ams only.
Scenario: a rogue site device, or a device a consumer is made to read, answers an object-list, a trend log's log-device-object-property, a group's member list or any array of object identifiers with device identifiers 0 to 4194302, a few hundred per reply, more when segmented. Each becomes a `Referenced` device record with its own virtual instance and MAC.
Consequence: table.json and the maps grow by about 150 bytes per identifier toward hundreds of megabytes; `table.write` (`table.go:286-299`) marshals the whole file once a second while holding the table lock, so every consumer lookup stalls for the write; the data directory fills; the next `Open` unmarshals it all. A5, A4 by size.
Standing: **gap.** No test grows the table through a value. Closes with: a referenced record is derivable, so it need not be stored, or it takes a token of the same admission bucket and the value is rewritten to the broadcast when there is none; and a hard cap on records with a refusal logged at warn.

**F4. Every per-source bound keys on the UDP port and the NPDU source, which the sender chooses; the allow list and the level key on the IP address.** Shifter. Threats D1, D2, D3, D7, O6. `server.Peer.Key` (`server.go:134-139`) is the address and port of an unrouted peer, and the NPDU's SNET and SADR for a routed one; `allowed` and `peerOf` use the address alone (`server.go:353`, `shifter.go:871`). The key is what the rate limit (`server.go:485`), the one-burst-per-interval Who-Is answer (`shifter.go:788`), the recent-peer map (`:663`) and the consumer's subscription cap (`cov.go:270`) count by.
Scenario: an admitted consumer sends each datagram from a new port, or sets the source-specifier bit and varies SADR. Every new key gets a full bucket of twenty, a new Who-Is burst, a place among the recent peers and its own 256 subscriptions; `max_sources` evicts the oldest key, so the supply never runs out. The flood test (`limits_test.go:63`) sends from forty ports and asserts only that goroutines and heap stay low, which they do because each handler is short; it does not assert the rate per address.
Consequence: `max_rps_per_source` bounds a client with one socket and nothing else; what bounds the consumer is the global in-flight cap, the site's `max_rps` and the site-side subscription caps, so one consumer can take all of the site's capacity (the residual the model noted for D7 is now trivial to reach), hold 1024 × 256 consumer subscriptions, and be told of each announcement a thousand times. Without the tunnel, a spoofing sender gets one I-Am per device per forged port at a victim (D2 reopened). Unconfirmed requests get a goroutine each with no cap but this rate (`server.go:511`).
Standing: **partial** with the tunnel, where the consumer harms its own share and the shifter's CPU; **gap** without. Closes with: key the limiter, the Who-Is burst, the recent peers and the subscription count on the IP address, and bound the distinct routed sub-peers per address; this is shifter-only.

**F5. A segmented reply can be made to resend any window at any rate and never ends while it is acknowledged.** Shifter. Threats D2, D4, O6. `server.continueReply` (`server.go:898-915`): a Segment-ACK resets the timer, takes its sequence number as the next segment with no check that it advances, and sends a window of the size the acknowledgement names, up to 255, not clamped to the four the server proposed. Replies are not rationed (`server.go:482-489`), since they are matched to the server's own transactions, but a Segment-ACK for a live transaction is one. A reply holds up to what the library reassembles, 64 segments of 1476 bytes.
Scenario: one ReadPropertyMultiple for a device's object-list gives a segmented reply; then a Segment-ACK for sequence 0 with a window of 255, repeated. Each 13-byte acknowledgement is answered with up to 94 kilobytes. With F4, fifty such replies a second (the site's `max_rps`) can be created and each kept alive forever, so `sending` grows without bound, each entry holding its payload. Without the tunnel the read and the acknowledgements can be sent in a victim's name, and the shifter is a reflector of several thousand to one.
Standing: **gap**; D4 moves from held to partial, since only the silent consumer is timed out. Closes with: clamp the window to the proposed one; take only an acknowledgement that advances the sequence, and resend a window at most once per timeout; a total lifetime per segmented reply; a cap on segmented replies per address.

### 2.2 Medium

**F6. Names and texts per site device are unbounded, and a renamed record is never pruned.** Shifter. Threat D8. `EnsureName` (`table.go:632-650`) keeps the old record marked renamed and appends a new one on every change; `TextsPerProperty` (`table.go:714-739`) caps the strings of one (device, object, property) key at sixteen, but the number of keys is uncapped, and the real string's length is uncapped (the library reassembles up to 94 kilobytes). A rogue device that answers object-name with a counter, read by a consumer at twenty requests a second, adds 72,000 name records an hour; one that answers every property of every object a consumer enumerates with a string adds a text key for each. `byPseudo` grows with them and Who-Has scans it. Standing: **gap.** Closes with the cap of F3: records per device and per table, and a length cap on stored strings.

**F7. A notification is fanned out on a goroutine per consumer with no queue and no cap.** Shifter. Threats D1, O6. `covDeliver` (`cov.go:453-455`) spawns one goroutine per consumer subscription per notification; for a confirmed subscription `covSend` then waits the server's timeout, three seconds, for an acknowledgement that a hostile consumer never sends. With F4 one address can hold 262,144 consumer subscriptions on the one object the site changes most often; each site notification then costs that many goroutines and datagrams. Even keyed by address, 256 subscriptions times a fast object times three seconds is thousands of goroutines per consumer. Standing: **gap.** Closes with: a bounded send queue per consumer that drops the oldest, and a global cap on consumer subscriptions.

**F8. The move confirmation can be won.** Shifter. Threat S2. `admit` (`shifter.go:484-502`) probes the old address once and surrenders the instance on a timeout or on `ErrNetworkUnreachable`. Three ways round it: a Reject-Message-To-Network from any sender for the old device's routed network makes the probe fail unreachable (F2, `routing.go:90-98`); a device reached through a BBMD whose registration lapsed is silent and is lost to any claimant; and the probe accepts any answer at all, an Error included, so it cannot tell the old device from another that took its address. `TestMoveConfirmed` covers the honest case only. Standing: **partial**, as the model said, and weaker than it read. Closes with: probe the old address twice over a longer window, require the answer to carry the instance, and treat a reject as "unknown" rather than "silent".

**F9. Repeated I-Ams for one known instance from many addresses each cost a probe.** Shifter. Threat D5. `admit` takes an admission token only for an unknown or referenced instance (`shifter.go:473-482`); a known one claimed from a new address goes to the probe path, so a thousand I-Ams for one instance from a thousand forged addresses are a thousand ReadProperty requests to the site, bounded by the four discovery slots and the site's `max_rps`, not by `max_new_devices_per_minute`. The name read, the announcement and the unicasts happen once per instance per run (`heard`), so those are bounded. Standing: **partial.** Closes with: ration moves per instance, one probe per interval.

**F10. The survey adopts whatever answers at an address.** Shifter. Threat S2. `knock` (`survey/survey.go:531-552`) records the instance an address answers with, and `adopt` (`shifter/survey.go:197-225`) feeds it to `discovered` through `Probe`; an address that answers with an instance the table holds for another address enters the move path of F8, now from subnets a Who-Is never reaches, which is the survey's purpose. Standing: **partial**, the same as F8 by another door. Closes with F8.

**F11. The peers ceiling is checked before the level is parsed.** Operator error made certain. `cmd/shifter/main.go:163` calls `parsePeers` with `cfg.Control` while it is still the zero value, `no-write`; the level is parsed at `:177`. Any `consumer.peers` entry at `limited` or `full-service` fails the start with "above control no-write, the ceiling", including the README's own example. `Validate` passes it, `config_test.go:83` calls `parsePeers` with the right ceiling, nothing calls `build`. The likely workaround is to delete the peers and serve everyone at the global level, which is the harm of T5. Standing: a bug, fail-closed. Closes with: parse the level first, and a test of `build`.

**F12. Audit lines are lost under a refusal flood, and a failing audit disk is never surfaced in the log.** Threats R2, A6. `audit.Record` (`audit.go:80-92`) drops a line when the queue of a thousand is full and counts it; `run` (`:95-116`) writes and syncs one line at a time and counts a write error, with no log line anywhere in the package. Every refusal is one line (`shifter.go:999`), and with F4 a consumer makes refusals at any rate; a disk that syncs a hundred lines a second fills the queue in seconds, and a legitimate write's line is then dropped with a probability that grows with the overload. The only report is the `detail` of a later line, which on a full disk is never written. Standing: **partial.** Closes with: a log line at warn when lines are lost or a write fails; coalesce repeated refusals from one source into a counted line, as the allow-list drops already are.

**F13. Unknown configuration keys are ignored.** Threat T5. `config.go:192` unmarshals into the defaults without `KnownFields`; `allows:` for `allow:`, `contorl:`, `real_value:` each take the default silently. For the allow list that is "every source", with the warning of decision 3 as the only sign. Standing: **gap.** Closes with: strict decoding, an error naming the key.

**F14. Octet strings and numbers pass unexamined.** Threats I1, I4. `downstream` replaces character strings (`translate.ReplaceStrings`), maps device identifiers, rewrites a BACnetAddress in the `[1] {network, mac}` form and the device-address-binding, and blanks the vendor identifier under the strict profile; everything else passes (`translate.go:59`, `:151`, `:178`). What crosses as a result where a device has it: `device-uuid` (property 507 of 135-2020, a sixteen-byte octet string unique to the physical device), a MAC or serial number in a proprietary octet-string or unsigned property, a six-byte BACnet/IP address in a proprietary octet string. The sim has none, so the leak test cannot see it. Standing: **gap** where the equipment has them; the README's list of what knowingly crosses does not name them. Closes with: replace octet strings through the table like strings unless the property passes, or hide 507 and any six- or sixteen-byte octet string; a canned device with such a property in the test.

**F15. Three paths put real values in the log past `log.real_values: false`.** Threat I9. `redact.go:15-18` names the keys. Outside them: `shifter.go:320` logs the real site network number of an unmapped address under `network`, a key that otherwise carries virtual numbers; `shifter/survey.go:184` logs the survey summary under `result`, a preformatted string that begins with the surveyed subnet or ranges (`survey/report.go:46-63`); and error values under `error`, `answer` and `err` carry the library's texts, which name site addresses for `ErrSubscribed` (`client/cov.go:153`), for a send failure (a `net.OpError` from `WriteToUDPAddrPort`) and for a router's reject (`routing.go:97`). The redaction test runs a healthy sim and sees none of them. Standing: **partial.** Closes with: redact `network` on that line, log the summary's parts under their keys, and redact error values when the log is redacted.

**F16. The audit file holds real values and lives wherever `audit.file` points.** Threat I11. Every write, refusal and subscription line carries `real` (`audit.go:37`), and the `outcome` of a failed send is the error text with the site address (`write.go:189-191`). The path is any path (`config.go:87`), created 0600, which NTFS ignores; `host.CheckDir` covers `data.dir` only (`main.go:82`). A relative path or a logs share with an inherited ACL gives others the virtual-to-real map. Standing: **partial.** Closes with: check the audit file's directory as the data directory is checked, or default it into the data directory.

### 2.3 Low

**F17. The Windows directory check has three gaps.** `host_windows.go:45` skips every ACE type but the plain allow, so a callback (conditional) or object ACE granting Everyone read passes; `:49` accepts the directory's owner unconditionally, so a directory the operator created and the service account runs in passes though the operator can read it, which the model tolerates; and the check is of the directory only, so a key or table restored with explicit ACLs from an open place is unchecked. The Unix check is sound.

**F18. The table is renamed into place without a sync, and a scheduled write's error is reported only at close.** `table.go:295-298` writes a temporary file and renames it with no `Sync`; after a power loss the rename can be durable while the data is not, and `Open` then fails on an empty file. Recovery by deleting it changes every pseudonym that was issued at a candidate above zero. `table.go:280` holds a write error in `lastErr` until `Close`, so a failing disk goes unreported for the run.

**F19. The audit log is off by default and nothing requires it at `full-service`; instance 0 is unattributable.** `Validate` passes `full-service` with a non-empty allow list and no `audit.file`, so A7 is recorded nowhere but stderr. `Device` and `Real` are `omitempty` (`audit.go:36-37`), so a write to a device whose instance is 0, which BACnet allows and the derivation can yield, is logged without its device.

**F20. DPAPI is user scope with no entropy, and a conversion leaves plaintext behind on failure.** `dpapi_windows.go:17`, `:31`: no optional entropy and no machine flag, so any process under the same account decrypts the key, which under a shared service account is every service on the host; `store.go:108-119` writes the plaintext to `key.tmp` before the rename when converting back to `file`.

**F21. The candidate suffix is not length-prefixed in the HMAC input.** `pseudonym.go:135-146`: a real name ending in `|#1` at candidate 0 hashes as the same name without it at candidate 1. It needs a prior collision on the same object and that rename; negligible, but the encoding is ambiguous.

**F22. Prefix parsing accepts what the operator may not mean.** `config.go:287-297`: `0.0.0.0/0` is accepted without the empty-list warning; `10.8.0.7/24` is accepted and matches as `10.8.0.0/24`; an IPv4-mapped IPv6 entry never matches, since every source is unmapped (`server.go:422`), which fails closed in `consumer.allow` and silently falls to the global level in `consumer.peers`.

**F23. The survey has no minimum interval, and its pings and neighbor reads are outside the site rate limit.** `RunSurvey` (`shifter/survey.go:143-174`) refuses a concurrent run only; `on_start` and the daily schedule are the only callers today. The BACnet probes go through the client's guard and limiter as the README says; the pings (`ping_windows.go:238`, unprivileged) and `arp -a` do not, and are paced by the survey's own `rate`.

**F24. The site's time zone crosses.** Threats I5, I6. `utc-offset`, `daylight-savings-status`, `local-date` and `local-time` are numbers and pass, and together they place the site in a time zone, which is a coarse location. An accepted exposure to add to the README's list, or two properties to hide.

**F25. The audit `peer` of a routed consumer carries a network and MAC the consumer wrote.** `server.Peer.String` (`server.go:125-130`) is the audit line's `peer`; for a routed consumer the network and MAC are the NPDU's, chosen by the sender; the `via` address and the `prefix` field are the identity. The value is a JSON string, so no line injection.

**F26. The library's read loop has no recover, and the translator's recursion has no depth limit.** `client.go:636` dispatches I-Ams and notifications inline; a panic there ends the site socket, with no test input known to cause one (the library fuzzes its parser). `translate.Values` and `ReplaceStrings` recurse into constructed values without a depth bound; on a notification that runs under the shifter's recover and costs one dropped notification.

**F27. Under `sim`, the audit log's `Close` is overwritten.** `main.go:175` and `:213`; lines are synced per write, so nothing is lost.

## 4. Residual risks, revised

To the list of threat model §10 add:

- **The time zone (F24).** Four numeric properties place the site in a zone.
- **Octet strings and numbers in proprietary properties (F14)**, until the octet-string rule is decided: the README's "what knowingly crosses" should name them, or the rule should close them.
- **An admitted consumer's share of the shifter** is, today, all of it (F4): the per-source bounds hold a client that misbehaves by accident, not one that means it.
- **A site host that speaks BACnet is trusted for what it says about addresses** (F1, F2): the site network is assumed well-behaved for integrity, and the library takes that assumption further than the model did, to every host on it.

## 5. What to close, in order

Three packages, in the plan's style, none started here.

1. **P7, the bounds keyed by address.** Shifter only. F4, F5, F7, F9, F12: key the limiter, the Who-Is burst, the recent peers and the subscription count on the IP address and bound the routed sub-peers per address; clamp the segment window, take only advancing acknowledgements, give a segmented reply a lifetime and cap them per address; a bounded notification queue per consumer and a global cap on consumer subscriptions; one move probe per instance per interval; a warn line when audit lines are lost and a coalesced refusal line per source. The flood test gains the assertion it lacks: datagrams accepted per address, not per port. This is the package that makes O6 true.
2. **P8, the table bounded and the operator's mistakes refused.** Shifter only. F3, F6, F11, F13, F16, F15, F14 if decided: referenced devices derived rather than stored or admitted through the bucket; caps on records per device and in all and on stored string length; the peers ceiling after the level; strict configuration keys; the audit directory checked; the three log lines; the octet-string rule or the README's list. With F18 and F19 as small items.
3. **L7, the library's address trust.** Library, the client's parsing, which its scope allows. F1 and F2: a Forwarded-NPDU believed only from the configured BBMD; a route learned from I-Am-Router-To-Network only and kept until the router is silent or rejects; a conflicting claim logged. F8 follows in the shifter once the probe can trust the route it goes by: two probes, the answer's instance checked, a reject counted as unknown. This is the package that makes the site side a boundary toward a rogue device, which the model listed as T4 and the plan never had a package for.

The external review the plan's §10 asks for before the shifter is described to anyone as a security layer stands; this assessment is an internal one and does not replace it.

## 6. Assumptions, re-read

## 7. Method

The consumer side (`internal/server`, `internal/shifter`, `internal/control`, `internal/translate`) was read in full by the author of this document. Two independent reviews were run in parallel over the storage, host, audit and configuration code (`internal/table`, `internal/pseudonym`, `internal/host`, `internal/audit`, `cmd/shifter`) and over the site side and the survey (`internal/survey`, the discovery and COV delivery paths, and the library's client). Every finding either review raised was checked at its lines before it was kept, and the lines cited are the ones read. What the reviews found sound is not listed here except where §1 relies on it: the key is 32 bytes from `crypto/rand`; the HMAC labels separate the kinds and put the object identity inside the hash, so equal real strings on different objects get different pseudonyms and there is no cross-object equality oracle; pseudonyms are fixed length; consumer strings never enter the table or the audit record; `json.Marshal` escapes the audit lines; the key and table are opened only after the directory check; the virtual network derivation skips the configured V and every taken number; strings inside constructed values in notifications are replaced; the Time-at-two-in-the-morning case is handled; a spoofed Who-Is cannot make a source recent.
